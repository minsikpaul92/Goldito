3. Decision tree

Each question, the options we tried, and why one won. Full log in DESIGN.md §0.

  1. D1

    Which look for the app?

    • ✓Balanced — warm neutrals, white cards, the same green
    • →Playful — prototypes only (outlines, shadows, fonts change too)
    • ✕Calm Core — dropped Oct 5

    Why: Balanced is closest to the code tokens, so it costs Minsik almost nothing. Playful changes structure, not just color: three weeks isn't enough to build and test it. Calm Core's tone is already covered by Balanced. Still the team's call.

  2. D2

    How do screens stay in sync with the design system?

    • ✓Components first, screens built only from instances
    • ✕Captured screenshots as layers

    Why: edit a component once and all 53 screens update. Component names match code (Button, Tag, Banner), so a Figma name tells Minsik which file to open.

  3. D3

    How is status color used?

    • ✓Status text on its own light surface (errorSurface, warningSurface, successSurface) via Tag and Banner
    • ✕Faded (opacity) copies of the status color

    Why: the audit found red text on a red tint below 4.5:1. Surfaces pass AA in every look, and red stays reserved for real problems.

  4. D4

    What outlines controls?

    • ✓borderStrong for anything you interact with, border for decoration, track for empty progress
    • ✕One border for everything

    Why: border is 1.3:1 — inputs and unselected chips were nearly invisible (WCAG 1.4.11 needs 3:1). Sitters use the app outdoors.

  5. D5

    What happens when the AI is unsure?

    • ✓Depends on the risk: safety fails closed (don't feed), everything else fails open to a person
    • ✕One error message for every AI failure

    Why: a wrong "safe" can hurt a pet, but a blocked handoff or a missing caption only slows people down. So the assistant hands health questions to the sitter, a photo check never blocks a handoff, a report can go out as plain chips, and an unreadable label means "don't feed".

  6. D6

    Type and motion

    • ✓System font in the app, Inter in Figma; 4 sizes (24 · 16 · 14 · 11); 3 durations (120 · 240 · 420 ms); Reduce motion respected
    • ✕A custom brand font; an 18 px subtitle size

    Why: no font download on the demo and a native feel, and Inter's metrics are close to SF and Roboto. Card titles use Body Strong (16/600), so the 18 px size was never used.

4. Edge cases

Five rules behind the 16 edge-state screens in Figma (Edge states · ①–③ / ④ / ⑤). Full table in DESIGN.md §10.

Never lose a sitter's tap

Offline check-ins and photos are saved on the phone, marked "Waiting to send", and sent on their own. A wrong tap has Undo for 5 s.

Tell the owner before they ask

Late ETA, a missing photo, or a handover to a person: the owner sees what happened and when the next update arrives. They never see a blank screen.

Unsure about safety means no

An unreadable label, a missing dose or an allergy conflict blocks the action, and the screen says how to unblock it.

Nothing new without the owner's OK

Facts the AI learned during a stay go into the Life Record only after the owner confirms them. Low ratings stay private.

Calm by default, red only for real

Declined bookings and late pills use info or warning, never error. Red is for failed payments and DANGER.

## 2. 완료한 것

### Phase 06 (케어 루프) — PR #48 머지
- **오너 케어 체크리스트 / 요청**: 칩(Meals · Medication · Walk · Heads-up) → 한 줄씩 → 표. 줄마다 AI가 따로 다듬고(실패하면 오너가 쓴 그대로), 돌보는 중이 아니면 **자동 저장 + Undo**.

- **시터 Home**: 한 화면, 오늘 할 일 목록(시간 전에도 보임, 일찍 Done 가능), 시간이 되면 **알람 팝업**(10분 스누즈), 요청이 오면 한 줄 안내.
- **체크인**: 탭으로 고르고 → 메모·사진(선택) → **Send**.
- **오너 Home**: Live updates(읽은 건 사라짐, 안 읽은 거절은 고정, counter-request는 답할 때까지 남음), 사진 썸네일과 큰 보기, "In care" 펫 카드, History, 알림 목록(밀어서 삭제 · Clear all).

### Phase 07 (알림장 AI) — PR #49
- **7.2** `POST /api/ai/daily-report`: 시터가 그날 맡은 시간의 기록만 모아 `source_snapshot` 하나를 만들고(모델 입력의 전부) Nemotron Super가 시터 1인칭 초안을 쓴다. 같은 날 다시 만들면 덮어쓰고, 이미 보낸 알림장은 409. 기록이 하나도 없으면 고정 문장(모델 호출 없음).
- **7.4** 프롬프트: **오너가 쓴 펫 정보(메모 · 알레르기 · Heads-up · 할 일의 용량/메모)가 기본 바탕**. 단 "배경일 뿐 오늘 일어난 일이 아니다". few-shot 3편, `PROMPT.md`, 실제 모델 점검 스크립트(`backend/scripts/check_daily_report.py`), 규칙을 어기면 한 번 다시 쓰게 하는 사후 검사(성별 대명사 · "on time").
- **7.5** `send_daily_report`: **시터가 고쳐서 보낸 최종 본문만** 게시, 오너는 보낸 것만 본다(AI 초안은 안 보임), 한 번만, 오너에게 `report_sent` 알림.

## 5. 알려진 한계 · 결정 기록
- **"a week"(주 단위 반복)는 없음**: 할 일은 매일 반복이거나 한 번뿐. 필요하면 일정 모델 확장이 먼저.
- **횟수 방식은 카운터가 아니라 시간 자동 배치**("3 times a day" → 8 AM · 2 PM · 8 PM, 표에서 수정 가능).
- **counter-request의 추가 비용은 기록·표시만** 한다(데모에 추가 결제 없음).
- **요청 승인은 한 번에 하나**: 펫당 열린 요청(대기 또는 counter) 1건.
- **돌보는 중 수정·삭제**: 이미 있는 할 일의 수정·삭제는 오너가 직접 할 수 있다(추가만 요청으로).
- **승인 시점 오류**: 요청은 보낼 때 검증하지 않고 승인할 때 만들어진다. 앱은 글자 수와 종 규칙을 미리 막지만, 규칙에 어긋난 요청은 승인할 때 오류가 날 수 있다.
- **서버 푸시(6.7)는 건너뜀**: 앱이 꺼진 상태의 알람은 불가. 알람 팝업은 앱이 열려 있을 때만(소리·진동은 브라우저가 허용할 때).
- **시터 Diary · Pet Transit 화면은 아직 없음**(오너 Diary 탭은 안내 화면).
- **알림장 말투**: `tone.compose()`(7B.8)가 없어 기본 예시를 쓴다. 모델 문장이 가끔 어색하다 — 시터가 미리보기에서 고친다.
- **AI 환각 방지의 구조**: 모델에는 `source_snapshot` 하나만 주고, 기록이 없으면 모델을 부르지 않으며, 규칙 위반은 한 번 다시 쓰게 한다. 프롬프트를 바꾸면 `check_daily_report.py`를 다시 돌려 사람이 읽는다.

## 6. 개발 환경 메모 (함정 위주)
- **서버**: 백엔드 `cd backend && .venv/bin/uvicorn app.main:app --port 8000`, 프론트 `cd frontend && npx expo start --web --port 8081`. 둘 다 `.claude/launch.json`에 있음.
- **Playwright(flows)**: 목(mock) Supabase용 빌드가 따로 필요하다. `EXPO_PUBLIC_*`를 `.github/workflows/ci.yml`의 값으로 주고 **`npx expo export -c -p web`**(`-c`로 캐시를 지워야 `.env`의 실제 값이 섞이지 않음) → `npx playwright test --project=flows`. 커밋은 **전체가 연속 3번 통과**한 뒤에. 시간에 따라 달라지는 테스트는 만들지 않는다(가짜 시계 또는 DB 상태로 확인).
- **SQL 스모크**: 일회용 `postgres:17` 컨테이너에 `supabase/tests/supabase_stub.sql` → `supabase/migrations/*.sql` → `rls_smoke.sql`(CI와 같은 순서). 같은 컨테이너를 재사용하지 말고 매번 새로 만든다(역할이 남음).
- **백엔드**: `pytest.ini`가 `tests/`만 수집(라이브 스크립트가 테스트로 돌지 않게). Mac의 Python은 `certifi`로 TLS 인증서를 지정해야 JWKS를 가져온다(`app/deps/auth.py`).
- **Prettier**: 기존 파일에 돌리지 않는다(관련 없는 줄이 바뀜).

## 2. P0

<a id="sr-1"></a>
### SR-1 · 성분표가 일부만 읽혀도 SAFE + "double-checked" (P0 · 높음)

**현상**
- 사진에서 성분표 끝부분이 잘리면(마늘 · 자일리톨이 흔히 있는 자리), 읽힌 앞부분만으로 규칙과 Ultra가 판단해 **SAFE**("Looks fine for Max ✅", `double_checked: true`)가 나온다.
- 모델이 목록을 쉼표로 나누지 않고 한 줄로 주면, 120자 뒤가 말없이 잘린다. 예: `"peanut butter, oat flour, …, citric acid, xylitol"`(129자) → `xylitol`이 사라져 SAFE (전체 문자열이면 DANGER).
- 성분이 60개를 넘어도 61번째부터 말없이 버려진다.

**원인**
- [`backend/app/ai/prompts/safety/vision_system.md:12`](../../backend/app/ai/prompts/safety/vision_system.md) — "If only part of the list is readable, return the part you can read and set `readable` to true." 목록이 불완전하다는 신호가 응답에 없다.
- [`backend/app/routers/ai_safety_check.py:41-49`](../../backend/app/routers/ai_safety_check.py) `_clean_list` — 항목마다 `text[:120]`, 전체 `out[:60]`. 잘렸다는 표시를 남기지 않는다.
- 같은 파일 `safety_check()` 250–258줄 — 판정은 `rules.status`와 `judgement.safety_status`만 본다.

**해결책**

1. **비전 프롬프트에 `complete` 필드** (`vision_system.md`)
   - 예시 JSON: `{"readable": true, "complete": true, "product_name": "...", "ingredients": [...]}`
   - Fields에 추가:
     > `complete`: true only when you can see the whole ingredient list, from its first item to its last — the list ends inside the photo, or is followed by another section such as the guaranteed analysis. false if the list runs off the edge of the photo, is covered, or you could not read some items.
   - 12줄을 바꿈:
     > If only part of the list is readable, return the part you can read, set `readable` to true and `complete` to false.

2. **목록 정리 함수가 "잘림"을 돌려줌** (`ai_safety_check.py`)

   ```python
   MAX_INGREDIENTS = 60
   MAX_ITEM_CHARS = 120
   _SPLIT = re.compile(r"[;,]")


   def _clean_items(value, limit: int = MAX_INGREDIENTS) -> tuple[list[str], bool]:
       """Tidied, de-duplicated items, and whether anything had to be dropped (too many, or too long even re-split)."""
       if not isinstance(value, list):
           return [], False
       out: list[str] = []
       cut = False
       for item in value:
           text = " ".join(nebius.strip_think(str(item)).split()).strip(" .;:").lower()
           # A whole list sent as one string: split it again instead of cutting it at 120 characters.
           parts = [text] if len(text) <= MAX_ITEM_CHARS else [p.strip(" .;:") for p in _SPLIT.split(text)]
           for part in parts:
               if not part:
                   continue
               if len(part) > MAX_ITEM_CHARS:
                   cut = True
                   part = part[:MAX_ITEM_CHARS]
               if part not in out:
                   out.append(part)
       if len(out) > limit:
           cut = True
       return out[:limit], cut


   def _clean_list(value, limit: int = MAX_INGREDIENTS) -> list[str]:
       return _clean_items(value, limit)[0]
   ```

   `Judgement`의 목록 필드는 지금처럼 `_clean_list`를 쓴다.

3. **`LabelReading`에 `complete` · `truncated`**

   ```python
   class LabelReading(BaseModel):
       readable: bool = False
       # None: the model did not say (older prompt) — not treated as partial, but logged.
       complete: bool | None = None
       product_name: str | None = None
       ingredients: list[str] = Field(default_factory=list)
       # Set by the server, never by the model: the list had to be cut.
       truncated: bool = False

       @model_validator(mode="before")
       @classmethod
       def _tidy(cls, data):
           if isinstance(data, dict):
               items, cut = _clean_items(data.get("ingredients"))
               data = {**data, "ingredients": items, "truncated": cut}
           return data
   ```

   기존 `_ingredients` field_validator는 지운다(두 번 정리하지 않게).

4. **판정 단계** (`safety_check()`, 250줄 "Never lower than the rules" 블록 뒤)

   ```python
   partial = label.complete is False or label.truncated
   if label.complete is None:
       log.info("safety-check: vision did not say whether the list is complete")
   if partial:
       raised = safety.worst(final, "WARNING")
       if raised != final:
           # Only the missing part made it WARNING: say that, not a rule sentence.
           message = safety.partial_message(pet["name"])
       final = raised
   ```

   - `safety.py`에 추가:

     ```python
     def partial_message(pet_name: str) -> str:
         return (
             f"We could only read part of the label, so we can't call this safe for {pet_name}. "
             "Retake a photo of the whole ingredient list."
         )
     ```

   - 이미 DANGER면(보이는 부분에 자일리톨) 그대로 DANGER, 메시지도 그대로.
   - Ultra에게도 알린다: `facts["label_complete"] = not partial`, `reasoning_system.md` Rules에 한 줄 — "If `label_complete` is false, never return SAFE: part of the list is missing."

5. **응답 · 저장** — `SafetyCheckResponse`에 `partial_label: bool`. `result_json`은 `result.model_dump()`라 자동으로 들어간다. `result_json`에 `"label_complete": label.complete`도 남긴다(나중에 모델이 이 필드를 잘 주는지 볼 수 있게).

6. **프론트** (`frontend/features/snap/treatApi.ts`, `TreatCheckScreen.tsx`)
   - `SafetyResult`에 `partial_label: boolean`, `fromRow`에 `partial_label: r.partial_label ?? false`.
   - `ResultCard` — `double_checked` 문구 위에:

     ```tsx
     {result.partial_label ? (
       <Text style={styles.note} testID="treat-partial">
         We could only read part of the label. Retake a photo of the whole ingredient list.
       </Text>
     ) : null}
     ```

   - 버튼 문구: `unreadable || result?.partial_label ? "Retake photo" : result ? "Check another treat" : "Snap a label"`.

**테스트**
- pytest `tests/test_ai_safety_check.py` (기존 fake 모델 `setup` 사용, 알러지 없는 펫):
  - `test_a_partly_read_label_is_never_safe` — 비전 `{"readable": true, "complete": false, "ingredients": ["oat flour"]}`, Ultra SAFE → `safety_status == "WARNING"`, `partial_label is True`, 메시지에 "only read part".
  - `test_a_list_sent_as_one_string_is_split_again` — 129자 한 줄 끝에 `xylitol` → DANGER, `detected_ingredients`에 `"xylitol"`.
  - `test_more_than_sixty_ingredients_is_partial` — 61개, 61번째 `xylitol` → SAFE 아님(`partial_label`).
  - `test_a_complete_label_stays_safe` — `complete: true` + 무해 → SAFE, `partial_label is False` (회귀 방지).
- e2e `frontend/e2e/treat-check.spec.ts` — 목업 응답에 `partial_label: true`, `safety_status: "WARNING"` → `treat-partial` 보임, 버튼 "Retake photo".
- 👤 실제 모델: 샘플 라벨 4장 + 끝을 가린 사진 1장으로 `complete` 값을 확인 → [model-ids.md](phases/notes/model-ids.md)에 기록. 모델이 `complete`를 자주 빼먹으면(`None`) 민식에게 알리고 기본값을 정한다.

**완료 기준** — 목록이 불완전하다고 알 수 있는 모든 경우(모델이 `complete: false`, 항목 잘림, 60개 초과)에 SAFE가 나오지 않는다. 기존 테스트 전부 통과.

### SR-2 · 알러지 매칭 누락 — 자유 입력 · 단어 경계 (P0 · 중간)

**현상** — 실제 규칙 파일로 확인한 **SAFE 오판**(규칙이 DANGER를 내야 함). Ultra까지 놓치면 그대로 SAFE:

| 펫 알러지(입력한 그대로) | 라벨 성분 | 지금 규칙 | 맞는 답 |
| :--- | :--- | :--- | :--- |
| `eggs` | dried egg product | SAFE | DANGER |
| `poultry` | chicken breast | SAFE | DANGER |
| `milk` | sodium caseinate | SAFE | DANGER |
| `fish` | fishmeal | SAFE | DANGER |
| `fish` | catfish | SAFE | DANGER |
| `dairy` | buttermilk powder | SAFE | DANGER |

**원인**
- 펫 알러지는 자유 입력이다(앱은 소문자로만 바꿈, 고르는 목록 없음).
- [`backend/app/ai/safety.py:38-42`](../../backend/app/ai/safety.py) `allergen_words` — `toxic_rules.json`의 `allergen_aliases`를 **정확한 키**로만 찾는다. `eggs` · `poultry`는 키가 없어 그 단어 하나만 찾는다(`eggs`는 "dried egg product"에 없음).
- [`safety.py:29`](../../backend/app/ai/safety.py) `_mentions` — `(?<![a-z])word(?![a-z])` 단어 경계. `casein`이 `caseinate`, `fish`가 `fishmeal` · `catfish`, `milk`가 `buttermilk`를 못 잡는다.

**해결책** — 부분 문자열 매칭으로 바꾸지 **않는다**(SR-3 같은 오탐이 늘어남). 대신 **키 정규화 + 라벨 표기 alias 보강**.

1. **`toxic_rules.json`에 `allergen_keys`** — 사람이 적는 이름 → 표의 키:

   ```json
   "allergen_keys": {
   ```

**해결책** — 서버에서 **박스 중심 거리로 추적**한다(프론트 변경 없음).

```python
import math

MAX_TRACK_JUMP = 0.3  # a pet moves at most this far (fraction of the frame) between two of the four frames


def _centre(box: Box) -> tuple[float, float]:
    return (box.x + box.w / 2, box.y + box.h / 2)


def _tracks(frames: list[Frame]) -> list[tuple[int, int, int]]:
    """(frame position, crop position, track): the same pet across frames, matched to the busiest frame by box centre."""
    anchor = max(range(len(frames)), key=lambda fi: (len(frames[fi].crops), -fi))
    anchors = [_centre(c.box) for c in frames[anchor].crops]
    out: list[tuple[int, int, int]] = []
    for fi, frame in enumerate(frames):
        pairs = sorted(
            (math.dist(_centre(crop.box), a), ci, ti)
            for ci, crop in enumerate(frame.crops)
            for ti, a in enumerate(anchors)
        )
        used_crops: set[int] = set()
        used_tracks: set[int] = set()
        for dist, ci, ti in pairs:
            if ci in used_crops or ti in used_tracks or dist > MAX_TRACK_JUMP:
                continue
            used_crops.add(ci)
            used_tracks.add(ti)
            out.append((fi, ci, ti))
    return out
```

### SR-17 · 스티커 오리기: 폴백이 안 탐 · 워커 종료 / 타임아웃 없음

**현상**
- classic 워커 안에서 `import()`가 안 되는 브라우저에선, 워커가 `{ok: false, error: "<메시지>"}`를 보내는데 `segmentAt`은 메시지가 정확히 `"worker"`일 때만 메인 스레드로 폴백 → 탭할 때마다 오류.
- CSP가 `blob:` 워커를 막으면 `new Worker`가 던지고 `waiting`에 고아 항목이 남음.
- 워커 · 로드한 모델(30 MB)이 세션 내내 메모리에 남음, blob URL revoke 안 함, 오류 때 `bitmap.close()` 건너뜀. 모델 다운로드가 멈추면 "cutting" 스피너가 영원히, Pick 버튼도 비활성.

**원인** — [`cutout.ts:44-47`](../../frontend/features/snap/cutout.ts)(워커 catch), 54–86줄(`getWorker` · `inWorker`), 125줄(`!== "worker"` 조건).

**해결책**
1. 워커 안에서 **로딩 단계** 오류를 구분해 보냄:

   ```js
   } catch (error) {
     try { bitmap.close(); } catch (_) {}
     self.postMessage({ id, ok: false, stage: ready ? "segment" : "load", error: String((error && error.message) || error) });
   }
   ```

   (`ready.catch(() => { ready = null; })` 때문에 로딩 실패면 `ready`가 `null` → `"load"`.)
2. `Reply` 타입에 `stage?: "load" | "segment"`. `segmentAt`:

   ```ts
   } catch (error) {
     const e = error as Error & { stage?: string };
     // The worker could not even load MediaPipe (no import() in classic workers, CSP): try the main thread once.
     if (e.message !== "worker" && e.stage !== "load") throw error;
     workerBroken = true;
   }
   ```

   `inWorker`에서 `if (!reply.ok) throw Object.assign(new Error(reply.error), { stage: reply.stage })`. 메인 스레드도 실패하면 그 오류를 보여 준다(진짜 네트워크 문제).
3. `inWorker`: `getWorker()`를 `try`로 감싸 던지면 `waiting.delete(id)` 후 `throw new Error("worker")`. 타임아웃 90 s(첫 모델 다운로드 포함):

   ```ts
   const timer = setTimeout(() => {
     waiting.delete(id);
     resolve({ id, ok: false, error: "Couldn't cut out your pet in time. Try again." });
   }, 90_000);
   // resolve 경로에서 clearTimeout(timer)
   ```

4. 정리: `let workerUrl: string | null` 보관, `export function disposeCutout()` — `worker?.terminate(); worker = null; if (workerUrl) URL.revokeObjectURL(workerUrl); workerUrl = null; waiting.clear()`. `StickerScreen`의 언마운트 `useEffect` 정리에서 호출(모델은 다음에 다시 받지만 1시간 캐시).

**테스트** — 단위 테스트 환경이 없으면 👤: 크롬 DevTools → Network offline에서 첫 오리기 → 90 s 뒤 오류 창, 다시 online → 재시도 성공. `sticker.spec.ts`는 훅을 쓰므로 그대로 통과해야 함.

### SR-19 · AI 엔드포인트 호출 한도 없음

**현상**
- 백엔드 전체에 rate limit이 없다. `/api/ai/pet-mood`는 `pet_id` 없이 로그인만 하면 부를 수 있고(가입은 열려 있음), 요청 하나에 비전 최대 16회(크롭 8 × JSON 재시도) + 요약 2회. 요청마다 스레드 풀이 따로라 전체 상한도 없다.
- `/api/ai/safety-check`는 Tavily 크레딧(월 한도) 최대 4 + 비전 + Ultra. 같은 `media_id`를 무제한 재검사할 수 있고, 시터의 DANGER 재검사마다 견주에게 알림이 새로 간다.

**해결책**
1. **사용자별 분당 한도** — `backend/app/deps/rate_limit.py` (Render 무료는 인스턴스 1개라 메모리로 충분):

   ```python
   import threading
   import time
   from collections import defaultdict, deque

   from fastapi import Depends, HTTPException, status

   from app.deps.auth import CurrentUser, get_current_user

   _hits: dict[tuple[str, str], deque[float]] = defaultdict(deque)
   _lock = threading.Lock()


   def per_minute(name: str, limit: int):
       """A dependency: at most `limit` calls a minute per signed-in user for this endpoint."""

       def check(user: CurrentUser = Depends(get_current_user)) -> CurrentUser:
           now = time.monotonic()
           with _lock:
               calls = _hits[(name, user.id)]
               while calls and now - calls[0] > 60:
                   calls.popleft()
               if len(calls) >= limit:
                   raise HTTPException(status.HTTP_429_TOO_MANY_REQUESTS, detail="Too many tries — wait a minute.")
               calls.append(now)
           return user

       return check
   ```

   라우터: `user: CurrentUser = Depends(rate_limit.per_minute("safety-check", 6))`, pet-mood는 10.
2. **같은 사진은 잠깐 동안 다시 계산하지 않음** — `safety_check()`에서 media 확인 뒤, 같은 `media_id`로 **10분 안에** 저장된 `safety_checks` 행이 있으면 그 행의 `result_json`으로 응답(새 insert · 새 알림 없음). 10분이 지났으면(그새 알러지를 고쳤을 수 있음) 새로 계산. 다른 펫으로 같은 사진을 검사하는 경우는 media의 `pet_id`가 고정이라 생기지 않는다.
3. 프론트: `ApiError.status === 429`면 오류 창 문구 그대로("Too many tries — wait a minute."), Retry 없음.

Phase 10 고정 데모 계정(심사위원이 같은 계정 공유)과 함께 한도 숫자를 정한다.

**테스트** — pytest: 7번째 safety-check 호출 → 429(fake 모델은 6번만 불림), 같은 `media_id` 두 번(10분 안) → 두 번째는 모델 호출 0회 · `safety_checks` 행 1개.

## 5. 잘한 점 (바꾸지 말 것)

- **Treat check 판정:** 최종 상태는 규칙보다 낮아지지 않고(`worst`), Ultra가 없거나 JSON이 깨지면 SAFE가 아님(fail-closed) — 테스트도 있음.
- **권한:** 역할별(견주 = 펫 주인, 시터 = 근무 중) + "본인이 올린 그 펫의 `safety_label` 사진"인지 확인. 이미지는 DB의 Cloudinary `public_id`로만 가져와 SSRF 없음. Tavily 도메인 제한은 요청과 서버 양쪽에서. `safety_checks`에 클라이언트 insert 정책이 없어 DANGER 알림을 위조할 수 없음.
- **AlertModal:** 불투명 전체 화면, 바깥 클릭 · Esc로 안 닫힘, 펫 스킨이 못 바꾸는 고정 빨강 — CLAUDE.md §3-4 그대로. e2e가 폰 프레임 안에 있는지도 확인.
- **Mood:** 모델은 정해진 태그만 고르고 서버 규칙이 %를 계산 → 같은 사진 같은 결과, 합 100 보장(0으로 나누기 없음, 모르는 태그는 `not_visible`). 장난감 규칙도 좋음.
- **재시도:** Treat check는 이미 올린 사진으로, Mood는 같은 크롭으로 다시 보냄 — e2e가 둘 다 확인.
- **마이그레이션:** SECURITY DEFINER에 `search_path` 고정, 새 테이블은 `revoke all` + 최소 grant, `acknowledged_at`만 바꿀 수 있는 컬럼 grant 유지, 스티커는 본인의 `sticker` 업로드만 행으로(`media_id` unique).
- **스티커:** PNG 투명도가 업로드부터 다운로드까지 유지되고 e2e로 확인. 견주 · 시터 레이어가 행으로 분리돼 서로 덮어쓰지 않음. "글 아래" 스티커를 편집 중 위로 띄워 잡게 한 처리, 드래그 중 DOM 순서를 바꾸지 않는 처리.
- **문서:** 단계마다 커밋 + TODO · test-guide 갱신, 사람이 할 일 분리 — CLAUDE.md 루프를 잘 따름.
